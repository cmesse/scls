- [x] **D1. gperftools without libunwind on RPM** (open_issues §1, §8). **Approved 2026-10-03.**
      Pass `CPPFLAGS=-I%{prefix}/include LDFLAGS=-L%{prefix}/lib` in the recipe (or fix the RPM env),
      make configure fail when libunwind is not found, and bump to 2.18.1-2. No cascade.
- [x] **D2. scotch compression: ON everywhere.** **Approved 2026-10-03**, on condition that it opens
      no dependency rabbit hole on macos or lbl. Planned implementation (still goes through the audit
      gate):
      - Replace the inert `COMMON_FILE_COMPRESS_*` flags with an explicit
        `-DUSE_ZLIB=ON -DUSE_BZ2=ON -DUSE_LZMA=ON`, and make a missing library a build failure, not a
        silent fallback.
      - Linux (gcc/mkl/debug/lbl): `rpm_build_requires` zlib-devel, bzip2-devel, xz-devel;
        `rpm_requires` zlib, bzip2-libs, xz-libs. These are stock EL BaseOS packages, so lbl is
        covered. Add the runtime names `bzip2-libs` → `libbz2-1.0` and `xz-libs` → `liblzma5` to
        `packaging/system_packages.yaml` (the -devel names are already mapped).
      - macos: the SDK has zlib and bzip2 but no `lzma.h` (Christian checked, 2026-10-03).
        Proposal: a new `xz` recipe (currently 5.8.3), built in the stack only where the flavor has no system
        xz. Linux flavors declare the system copy (`system_libraries: xz: true`, next to `zlib`);
        macos builds it, like gmp/mpfr/openssl. If a flavor claims the system copy and `lzma.h` is
        missing, the build fails instead of silently dropping lzma. Configure: LFS ch. 6 adapted:
        `--prefix=<prefix> --disable-static`, library only (`--disable-xz --disable-xzdec
        --disable-lzmadec --disable-lzmainfo --disable-scripts`), and remove `liblzma.la`. Not pinned
        (Christian, 2026-10-03); only the two backdoored releases, 5.6.0 and 5.6.1 (CVE-2024-3094),
        are banned. The update checker gets `exclude_pattern: '^5\.6\.[01]$'`, and a
        `configure.pre` guard refuses to build either version. Approved by Christian 2026-10-03,
        pending audit.
      - Bump the release to 7.0.15-2. The cascade (from `build_order.py`) is added to §2 before
        spral/ipopt.
- [x] **D3. Triplet-prefixed program names.** **Approved 2026-10-03: drop `--target`** (Christian;
      round 2 is the final round over all distros, so D3 joins it). No triplet-prefixed program ships on
      any flavor (gcc/binutils' upstream triplet drivers exempt); hwloc's tools, if shipped, use
      plain names. Whether to ship them at all follows the jury round on SCLS scope (Christian,
      2026-10-03: "we still can ship the hwloc tools if it makes sense for the scope of scls"); a packaging guard enforces it; libunwind's
      test programs (`libexec/libunwind/`) stop shipping. hwloc and libunwind get release bumps.
      `--target` dates from the builder's June 2025 commits (`bd87f8c`, `0d12006`), not a decision.
      gcc opts back in with `configure.defaults.target_flag: true`. Rows: hwloc 2.14.0-2,
      libunwind 1.8.3-3 (no consumer rebuild). Original (superseded) note: (open_issues §8, `build_common.py:684-686`). Still open.
      This renames shipped binaries on every Linux host (e.g. `lstopo` only exists as
      `x86_64-redhat-linux-lstopo`). Recommendation: a separate pass across all hosts.
- [x] **D4. Meta-package release.** **Approved 2026-10-03**: spral and ipopt are part of the new
      SCLS release, so they go into `scls-<F>`. `rpm_builder.py` (`Release: 1`) and `deb_builder.py`
      hard-code the meta release, so the rebuilt meta would reuse the published `scls-<F>-2026-1`
      NEVRA. Make the meta release a real field and ship `scls-<F>-2026-2` (`python/` change, audit
