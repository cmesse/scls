## gperftools: skip the pprof-dependent checks (`21f141e`)

**Decision (Christian, 2026-10-04):** option A, force the skip in the recipe; do not build Go to get
the Go pprof. Re-confirmed after the audits showed the skip covers five checks, two of which passed.
No release bump: "we only need to bump the package if the binary is already published", and
2.18.1-2 is not.

**Cause.** gperftools 2.18.1 enables five checks whenever any `pprof` is on `PATH` (upstream
`configure.ac:500-503`, `SKIP_PPROF_TESTS`) and expects the Go pprof. R10 has EPEL's Perl
`/usr/bin/pprof` (`pprof-2.15-4.el10_0`), R9 `pprof-2.9.1`. Observed in R9's build tree (see its
devlog): `profiler_unittest.sh` fails with "Unknown option: unit" (`--unit=ms`), and
`heap-profiler_unittest.sh` / `heap-profiler_debug_unittest.sh` with "Unknown option: hide"
(`--hide=`). On R10 before the change: 53 checks, 50 PASS, the same 3 FAIL; `sampling_test` and
`sampling_debug_test` PASS (`debug` build log from `f877482`).

**Change.** `recipes/gperftools.yaml`: `- "ac_cv_path_PPROF_PATH="` in `configure.args`. Upstream
`configure:23170` tests `${ac_cv_path_PPROF_PATH+y}`, so a set-but-empty value skips the `PATH`
search and `SKIP_PPROF_TESTS` is true. `PPROF_PATH` occurs only in `configure.ac`, `Makefile.am` and
`Makefile.in`; all five `if !SKIP_PPROF_TESTS` blocks (`Makefile.am:663, 675, 712, 725, 777`) wrap
tests. Trade-off accepted: `sampling_test` and `sampling_debug_test` are skipped too.

**Review.** Worked out with the R9 session, which agreed on option A and on a configure argument
rather than `configure.env`. Plan audits, blind: Codex (gpt-5.6-terra; R9 at high, R10 at medium)
and Grok (grok-4.7, high; R9 and R10): all "approve with changes". Changes taken: name all five
checks, name both rejected options (`--unit=ms`, `--hide=`), keep the token exactly
`ac_cv_path_PPROF_PATH=`, and rebuild already-built -2 RPMs at the same NEVRA, because `%changelog`
is rendered at build time. Implementation audits on R10 (Codex terra/medium, Grok 4.7/high): both
"approve with changes", none to the argument: (1) "installed files unchanged" was a claim until a
build proved it (now proved, below); (2) `todo/round2_el10_amzn2023.md` still said "don't fix it"
(corrected in this commit); (3) the observed evidence belonged in a tracked file (this entry and
R9's). Not taken: Grok's suggestion of a recipe guard that fails the build when configure still
finds a pprof. It is a further recipe change and needs its own approval; the gate below checks the
configure output on each host instead.

**Gate, real builds from `21f141e`** (R10: debug, gcc, mkl; R9: debug, gcc, mkl in its devlog):

- configure: `checking for pprof... (cached) no` and "pprof tool not found. Will skip several unit
  tests that need it", with `/usr/bin/pprof` still installed.
- suite: TOTAL 48, PASS 48, FAIL 0. No `sampling` or `profiler_unittest` name in the log.
- R10 debug, before/after comparison: `rpm -ql` 73 files, diff empty; `readelf -d` NEEDED of
  `libprofiler`, `libtcmalloc`, `libtcmalloc_minimal`, `libtcmalloc_debug`,
  `libtcmalloc_and_profiler`, `libtcmalloc_minimal_debug`, diff empty.
- `rpm -ql` counts 73 entries on debug and gcc and 72 on mkl. The payload is the same: on mkl two
  build-ids share one `/usr/lib/.build-id/dd` directory.
- NEVRA unchanged (2.18.1-2); `rpm -q --changelog` carries the pprof line.
- Spec: `--spec-only` renders `ac_cv_path_PPROF_PATH=` as the last configure word; `rpmspec -P`
  keeps it.

Still open, unchanged by this: the recipe pipes `make check` through `tee`, so a gperftools test
failure cannot fail the build. That is a separate decision.

## Host notes (R10)

- Builder Python: the system `python3` (3.12) has no `jinja2`, so `./scls build` failed before
  building anything. `flavor.conf` got `python: /home/mockbuild/Applications/python/bin/python3`
  (the venv that has `jinja2`) for the session; `flavor.conf` is restored and not committed.
- meson and ninja: that venv's whole `bin/` was on `PATH`, which the instructions forbid. Only
  `meson` and `ninja` are linked into `~/.local/bin`, and the builds ran with the venv directory
  removed from `PATH`.
- sudo: a persistent `NOPASSWD` rule for dnf, apt-get, dpkg and rpm (`sudo -n -l`); no keepalive
  was needed. `scripts/grant_pkg_sudo.sh --check` itself needs a password on this host.
- `bubblewrap` was installed with dnf, because the Grok wrapper's read-only sandbox needs `bwrap`.
  Codex and Grok had to be logged in again by Christian before the audits could run here.
