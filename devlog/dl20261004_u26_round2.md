## Changes Made / Proposed

- **Release-bump rule (`6e9e2e6`).** Christian, 2026-10-04, to this session: "we don't bump. New
  rule: only bump when the drop and publish has happened", and then "use common sense to adjust
  the policy doc". Written into `doc/BUILD_EXECUTION.md` §0.6 and `.claude/commands/update-plan.md`
  §4 (the cascade bump applies only to published NEVRAs). It replaces "one NEVRA per recipe state"
  for packages that are not published.
- **Audits for `d908cfc`, run on U26** because bwrap is blocked on U24. Plan and implementation,
  each blind, Codex (`gpt-5.6-terra`, `high`) and Grok (`grok-4.7`, `high`): all four "approve with
  changes". Taken from the plan audits: value `""` instead of `%{srcdir}/include`. Taken from the
  implementation audits: the changelog no longer calls the kept release "an exception"; the comment
  says the override makes the unix/deb builders skip the test as RPM already does; `ssmfet_c` stays
  out because the probe result is stored at `meson setup`, not because of `--no-rebuild`; "the
  BLAS/LAPACK part of the debug math line". The implementation audit read the diff as text against
  the pre-image, because the commit was not yet in this checkout.
- **How the fix reached U26.** A `git am` of the patch sent by the U24 session was denied by this
  session's permission guard. U24 pushed the commit to `origin/ipopt` itself and U26 pulled it.
- No recipe, flavor, manifest, patch or `python/` change was made on U26.
