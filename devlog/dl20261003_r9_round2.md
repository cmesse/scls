# R9 round 2: gperftools/libunwind, scotch compression, `--target` removal, spral + ipopt

**Date:** 2026-10-03
**Host:** R9 build host (Rocky 9.8, GCC 11.5.0), flavors debug, gcc, mkl
**Commits:** `cbdbf2b` (D1/D2/D4, xz), `e746bfe` (D3), merged with the macOS session's `1edbbc8`,
`1f16d16`. Tracker: `todo/r9_round2_20261003.md`. Other RPM hosts: `todo/round2_el10_amzn2023.md`.

## Decisions (Christian, 2026-10-03)

- **D1** gperftools links libunwind on RPM builds (`CPPFLAGS` on Linux + a configure check).
- **D2** scotch: gzip, bzip2 and xz graph-file support on every flavor, with declared dependencies.
  macOS and lbl get liblzma from the in-stack `xz` recipe; packaged flavors use the distribution's.
- **D3** The builder no longer passes `--target` to native autotools builds. No triplet-prefixed
  program ships on any flavor; gcc opts back in (`configure.defaults.target_flag`) and is exempt from
  the guard. hwloc's tools keep shipping, under plain names. libunwind's test programs do not ship.
- **D4** `scls-<flavor>` gets its own release (`meta_release: 2`) because spral and ipopt join it.
- Round 2 is the final round over all distros. spral and ipopt are part of the 2026 release.

## Review

Each change went through plan and implementation audits by Codex and Grok, blind to each other.
A jury round on D3 (five packaging-practice questions) was unanimous and matched the pre-registered
position. Findings that changed the work:

- gperftools: `CPPFLAGS` belongs in `platform_env.linux`, and the check must test `USE_LIBUNWIND`.
- meta: `build next` skips an already-installed meta, and `install _meta` handed dnf every
  `scls-<F>*` RPM (RPM) or picked by mtime (DEB). Both fixed.
- D3: the RPM guard aborted every clean package under `set -e` (found by a failed scotch build and,
  independently, by both auditors); `%install` inside a spec comment was parsed as a second section;
  gcc's `--target=%{host}` would have used rpm's `-gnu` triplet (Grok). All fixed in `e746bfe`; the
  fixes were checked by spec generation, `rpmspec -P` and the builds below, not by a third audit.

## Follow-up, 2026-10-04: gperftools pprof checks, and same-NEVRA rebuilds

- **gperftools pprof-dependent checks skipped on every host** (`21f141e`, implemented on R10, plan
  audits by Codex and Grok on both hosts; Christian: "Let's do option A", no Go build). Three checks
  failed because 2.18.1 expects the Go pprof and configure found EPEL's Perl `/usr/bin/pprof`:
  `profiler_unittest.sh` on `--unit=ms`, both `heap-profiler*_unittest.sh` on `--hide=`.
  `ac_cv_path_PPROF_PATH=` forces `SKIP_PPROF_TESTS`; that also drops `sampling_test` and
  `sampling_debug_test`, which passed. R9 gate on debug, gcc, mkl: configure prints "pprof tool not
  found. Will skip"; suite 48/48 (was 50 pass, 3 fail of 53); installed file list (73) and
  NEEDED/SONAME of all six libraries identical to the pre-change build; NEVRA stays 2.18.1-2.
- **Rule (Christian): bump only when the NEVRA is already published.** Nothing of round 2 is
  published, so gperftools 2.18.1-2, scotch 7.0.15-2 and libunwind 1.8.3-3 were rebuilt at the same
  NEVRA on all three flavors, so that the RPMs (including `%changelog`) match the recipes at
  `21f141e`. The "not rebuilt" note under the table above is superseded.
- Profiles for KCachegrind: a CPU profile written by the stack's `libprofiler` converts with EPEL's
  Perl `pprof --callgrind` (tested with a small program against `/opt/scls/gcc`; KCachegrind itself
  not run on this headless host). SCLS ships no pprof; upstream removed it in 2.17.
- lapackpp geev on R9 used `--dim 100:400:100` (64 runs); R10 ran the default dims (80 runs) under
  GCC 14.3.1.

## Open

- **Not staged, not uploaded.** Drops go out debug → gcc → mkl after the belfem coordinator's size
  OK and Christian's go-ahead.
- gperftools `make check` still runs through `tee`, so a test failure cannot fail the build. Changing
  that is a separate decision.
- libunwind has no `test:` block, so its upstream tests never run. Adding `make check` is a decision.
- Ipopt 3.14.20 (upstream): with an `hsllib` that cannot be loaded, Ipopt reports "Library loading
  failure" and then segfaults at exit in `Ma97SolverInterface::~Ma97SolverInterface` (null function
  pointer). Not caused by the SCLS build.
- `pkg-config --libs ipopt` carries no rpath; a user program needs `-Wl,-rpath,<prefix>/lib`.
- Passwordless sudo: no `/etc/sudoers.d/scls-build` on this host. Installs ran on a cached login with
  a `sudo -n -v` keepalive; one install failed when the cache lapsed. `scripts/grant_pkg_sudo.sh
  --user mockbuild --scope all --apply` is Christian's to run.
- `hwloc-dump-hwdata` (sbin) may not belong in a prefix install (Grok, jury round).
- macOS: `files/xz.txt`, hwloc's plain names and scotch against the stack liblzma need a real build.
