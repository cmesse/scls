## Key Findings

- **Round-2 defects on .deb.** libunwind and hwloc had the same triplet-prefix defect as on RPM
  (`x86_64-linux-gnu-*` programs in `bin/`, `libexec/libunwind`); both are gone after the rebuild.
  scotch -1 already linked `libz`, `libbz2`, `liblzma`, but its `Depends` listed only openmpi and
  environment; -2 declares `zlib1g`, `libbz2-1.0`, `liblzma5`. gperftools -1 already linked
  `libunwind.so.8` here, so the RPM defect did not occur on .deb; it was rebuilt because the
  recipe release changed.
- **Checks, all three flavors:** no triplet-prefixed file under the prefix; `bin/lstopo` present;
  `libprofiler.so` and `libtcmalloc.so` NEED `libunwind.so.8`; gperftools suite 48/48 with
  `checking for pprof... (cached) no`; SONAMEs unchanged (`libscotch.so.7.0`, `libhwloc.so.15`,
  `libunwind.so.8`); activate sets `OMP_CANCELLATION=TRUE` and leaves `OMP_PROC_BIND` unset; Ipopt's
  test step passes including hs071 with `linear_solver spral` ("Optimal Solution Found"); the
  meta-package depends on spral and ipopt. The multi-core run (`examples/hs071_cpp` from the Ipopt
  3.14.20 source against the installed prefix, `OMP_NUM_THREADS=8`, `linear_solver spral`) is
  optimal on all three.
- **libspral.so NEEDED:** debug `liblapack.so.3`, `libblas.so.3`; gcc `libopenblas.so.0`; mkl
  `libmkl_gf_lp64.so.3`, `libmkl_gnu_thread.so.3`, `libmkl_core.so.3`; all three `libgomp.so.1`,
  `libmetis.so.0`, `libhwloc.so.15`. No CUDA, no `libcblas`. `Library hwloc found: YES` in every
  setup log.
- **mkl:** Ipopt's configure finds MKL Pardiso; `scripts/check_mkl_linkage.sh --flavor mkl --prefix
  /opt/scls/mkl` PASS (451 ELF files, single layer `libmkl_gnu_thread`).
- **spral on debug failed before the fix.** The unix/deb builders put `<prefix>/include` on `CPATH`
  (`python/build_common.py:1082`), so SPRAL's `cblas.h` probe says YES and defines the C test
  `ssmfet_c`. The BLAS/LAPACK part of the debug math line is `-llapack -lblas`; the reference
  `libblas.so` exports no `cblas_*` symbol (`nm -D`: 0; `libcblas.so` has them), so the test did
  not link. RPM builds have no prefix `CPATH` at setup and skip the test, which is what
  `devlog/dl20261003_spral_recipe.md` recorded as "skipped" without naming the builder.
- **Test count differs by builder and flavor.** 9/9 on debug, mkl and every RPM build. 10/10 on
  gcc on the deb builder, where `ssmfet_c` is built and passes against OpenBLAS (U24
  `work/logs/gcc/spral.build.log`; U26 gcc reports the same). macOS should also expect 10.
- **`ssidst` and meson's 300 s per-test limit: host load, on every flavor.** Timings of the one
  test on U24 (and U26 for comparison):

## Changes Made / Proposed

- **`d908cfc` fix(spral):** `configure.flavor_env: debug: CPATH: ""`. Applied by
  `patch_common.apply_configure_environment` (unix/deb builders); `rpm_builder` never calls it, so
  RPM build steps are unchanged and generated specs differ only by the new `%changelog`
  paragraph (`--spec-only` diff for debug, gcc, mkl on U24). gcc, mkl, lbl and macos keep their
  `CPATH`. Rejected alternative: `-lcblas` on the debug line, which under `-Db_asneeded=false`
  would add `libcblas` to `libspral.so`'s NEEDED on debug only.
- **Release kept:** spral stays 2025.09.18-1 because it is not published yet (Christian,
  2026-10-04; `doc/BUILD_EXECUTION.md` §0.6). Hosts that already built spral -1 rebuild it at the
  same release. On U24, gcc and mkl spral were built from the final commit and debug was rebuilt
  from it at 15:42.
- **Review gate:** plan and implementation were each audited blind by Codex (`gpt-5.6-terra`,
  `high`) and Grok (`grok-4.7`, `high`). The audits ran on U26, because bwrap is blocked on U24
  (`kernel.apparmor_restrict_unprivileged_userns=1`, see
  `devlog/dl20260926_u24_openmpi_prrte_external.md`). Changes taken from the audits: value `""`
  instead of `%{srcdir}/include` (precedent `recipes/googletest.yaml`; an empty `CPATH` adds no
  directory on gcc 13.3 and 15.2), and five wording corrections in the comment and changelog.
- **Gate after the fix (debug):** `Has header "cblas.h" : NO`, `ssmfet_c` not built, meson test
  9/9, no `libcblas` in NEEDED.

## Open Questions

- **meson test timeout for spral (Christian).** `ssidst` is too close to 300 s on the Ubuntu VMs.
  A timeout multiplier in the recipe's test command (`meson test -t N`) is a recipe change and was
  not made. Until then spral on U24/U26 may need a quiet host and `MESON_TESTTHREADS=1`, and can
  still time out on any flavor.
- **`setup_environment` ignores `flavor_env` without `configure.env`** (`python/build_common.py:1104-1134`:
  the `flavor_env` block is nested inside `if 'env' in recipe['configure']`). It does not affect
  spral, whose configure step goes through `apply_configure_environment`, but it is a trap for the
  next recipe. Found by both auditors.
- **A host with a system-wide `cblas.h`** would keep the probe true on debug whatever `CPATH`
  says, and would need a patch to SPRAL's probe. Neither U24 nor U26 has one.
- **Auditor sandbox on U24** is still blocked (`todo/open_issues_20260927.md`).
- **U24 has 9.5 GB free** on `/`, below the 20 GB the execution doc asks for. It was enough for
  this run; cleanup (`scripts/prune_old_packages.sh`) was not run.
- RPM hosts and macOS: spral -1 is rebuilt at the same release there (Christian's part).
